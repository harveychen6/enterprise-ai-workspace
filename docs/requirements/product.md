# 产品需求：CareerDesk MVP

## 1. 定位

CareerDesk 是一个轻量的个人职业内容工具，打通「项目推进 → 经历沉淀 → 岗位匹配 → 定制简历」。

它同时是作者自己的日常工具，和一份可以公开克隆的开源项目。第一版的使用者是在本机运行应用的个人。没有账号，没有多人协作，没有作者托管的网站。

核心原则：

- **事实与成果分开。** 计划中、进行中、已完成是三种状态。规划不能写成已经达成的结果。
- **证据留在项目里。** 事实、数据、链接和待补问题先记在项目上，简历句子从这些材料里来。
- **母版与投递版分开。** 经历母版全局只有一份。投递版按岗位派生。投递版上改过的句子留在该版本里。
- **导航少。** 工作台只有项目、岗位、简历三个页面。高频操作在一两步内完成。

第一版界面语言为中文。文案集中维护，不在各组件里散落硬编码句子。不做多语言。

## 2. 信息架构

全局左侧栏固定三个入口：

1. **项目（素材库）**：进度看板和经历素材。
2. **岗位（目标库）**：目标 JD 与匹配结果。
3. **简历（编辑器）**：经历母版、投递版裁剪、导出。

布局跟随原型：左侧栏，而不是顶部三个 Tab。侧栏展示档案姓名，以及两个派生进度：

- 素材完整度 = 已写事实且没有待补问题的项目数 / 项目总数
- 投递准备度 = 已有投递版的岗位数 / 岗位总数

进度不单独入库。没有项目或岗位时，进度显示为空状态，不显示百分比。

## 3. 概念

| 概念 | 使用者能感知的内容 |
| --- | --- |
| 档案 | 姓名、抬头、年限、城市、联系方式、个人简介、技术栈、教育经历。第一次打开是空的 |
| 项目 | 标题、状态、摘要、技术标签、事实与证据、待补问题、简历描述、所属团队、起止时间 |
| 岗位 | 公司、岗位名称、JD 原文。城市、薪资、部门可空。另有关键词、匹配分、匹配到的项目 |
| 简历版本 | 母版全局一份。每个岗位最多一份投递版。版本里记录勾选了哪些项目，以及该版本自己的句子 |
| 合并提案 | 母版当前句子，与根据最新事实生成的新句子。计划中的项目不进入提案 |

城市、薪资、部门只用于岗位展示。匹配不依赖这三项。

## 4. 项目页

三列看板：计划中、进行中、已完成。卡片可拖拽改变状态。支持按名称或技术标签搜索。右上角可新建项目。没有项目时，看板各列为空，并提供新建和「导入示例数据」两个动作。

点击卡片，右侧滑出抽屉，自动保存，只包含：

1. **状态**：计划中 / 进行中 / 已完成。
2. **做了什么 & 证据**：Markdown 文本。记录背景、行动、数据、截图链接或 Git 记录。
3. **待补问题**：一行一条。记录缺的量化指标或未闭环的细节。
4. **简历描述**：准备放进简历的句子。可点击「AI 提炼」，从事实生成。

状态旁的说明：

- 计划中：不进入简历正文，只能作为技术栈了解项。
- 进行中：简历中必须能看出尚未完成。
- 已完成：可以写入成果，量化数据需要能在事实里找到。

「AI 提炼」在计划中项目上不生成成果句，只生成筹备中、尚未执行的说明。没有配置模型时，按钮不可用，并说明原因。已写好的事实和简历句仍可手改。

卡片展示标题、更新时间、摘要、标签、状态，以及待补问题数量。

## 5. 岗位页

左侧是岗位列表：公司、岗位名称、匹配度。右侧是详情和匹配区。列表按匹配度从高到低。

添加岗位时填写公司、岗位名称，并粘贴 JD 原文。城市、薪资、部门可选。保存后提取 3～5 个关键词，并与项目库计算匹配。

关键词标出两类：

- 项目的标签、事实或简历句里能找到原文
- 找不到原文，视为证据待补充

右侧列出最相关的 2～3 个项目和匹配原因。计划中的项目可以出现，并标明尚未执行。匹配原因要引用项目事实中的原句。

匹配度颜色：80 分及以上为绿，65–79 为黄，低于 65 为灰。分数来自规则，不由模型直接给定。

主操作是「生成投递版简历」。该岗位已有投递版时，打开已有版本。没有配置模型时，可以保存 JD，不能提取关键词和匹配原因。

## 6. 简历页

三栏：左侧版本，中间勾选，右侧预览和导出。

左侧置顶「经历母版」，下面是各岗位的投递版。

中间列出全部项目。投递版默认勾选该岗位匹配结果中状态不是计划中的项目。勾选计划中或进行中时，显示：

> 该项目尚未完成，建议在简历中标注进行中或仅作技术栈展示

右侧按勾选结果渲染简历：抬头来自档案，项目句子来自当前版本。投递版正文可以直接修改。修改只保存在当前投递版。母版纸面不可直接改写，句子通过项目简历描述和合并更新。

导出：

- **Markdown**：下载当前版本的文本。
- **PDF**：打开与预览同一套版式的打印页，由浏览器另存为 PDF。

未勾选的项目不出现在导出结果里。

档案为空时，预览仍可排版，抬头处显示待填写，并链到档案编辑。档案编辑放在简历页内，不新增第四个主导航。

## 7. 旅程

### 日常记录

打开项目，进入卡片，补充事实或待补问题，关闭抽屉。内容已自动保存。

### 同步母版

触发：

- 项目进入「已完成」，且事实比上次同步到母版更新。
- 打开应用时，距离上次同步超过设置的间隔，并且项目事实有更新。间隔默认 7 天，可在设置中修改。不绑定星期几。

出现横幅：「检测到 X 个项目有新进展，是否更新到经历母版？」

「查看并合并」打开左右对比：左边是母版当前描述，右边是依据最新事实生成的描述。计划中的项目被标为已忽略，不参与合并。

确认合并后，只更新经历母版。已经在投递版里改过的句子保持不变，并提示母版有更新，由使用者决定是否同步到该投递版。

没有配置模型时，不生成新的合并提案。已有的手工简历句仍可在项目抽屉里编辑。

### 针对岗位出简历

粘贴 JD，查看匹配到的项目，生成投递版，在简历页调整勾选和措辞，导出 Markdown 或 PDF。

## 8. 模型约束

凡是生成简历描述、合并候选句或匹配原因的请求，系统提示都包含：

> 仅基于提供的事实和证据进行提炼，严禁编造未提及的数据，严禁将「计划中」的事项描述为已达成的结果。

产品层拒绝这些结果：

- 句子中的数字在事实里找不到，且不能由事实中的两个数复核。
- 计划中项目被写成已达成结果。
- 进行中项目被写成已经全量上线，或句子里看不出「进行中」。

被拒绝的合并候选不能确认写入母版。

调用模型时才会把事实、待补问题和 JD 原文发往使用者配置的模型服务。看板、编辑、计分规则、Markdown 导出和 PDF 打印不访问该服务。

## 9. 示例数据

默认数据库是空的：空档案、空项目、空岗位、一份空白母版。

应用提供「导入示例数据」。示例使用原型中的虚构人物与项目，只用于演示三列看板、匹配和简历版式。导入前若库中已有内容，需要明确确认会写入示例，避免盖住真实档案。示例数据不是安装后的默认内容。

## 10. 验收

- 新建项目、拖拽改状态、刷新后事实仍在。
- 计划中项目的提炼结果不含成果数字；进行中项目的简历句含「进行中」。
- 改一份投递版的正文后，母版和其他岗位版本不变。
- 生成投递版时，计划中项目默认不勾选。
- 合并母版后，已有手工改写的投递版句子不变。
- 未配置模型时，可以记录项目、编辑简历、导出 Markdown 和 PDF。
- 首次启动看到空状态，而不是虚构人物的职业档案。

## 11. 不在本版

账号、多人协作、作者托管的在线服务、安装包、富文本编辑器、向量检索、定时邮件、在线分享链接、多语言、插件市场。
