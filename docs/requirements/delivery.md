# 开源交付需求：CareerDesk MVP

## 1. 交付物

第一版交付一个公开的 Git 仓库。使用者克隆仓库，在自己的电脑上安装依赖并启动，然后用浏览器打开本机地址。

仓库即产品，包含：

- 可运行的应用源码
- 数据库迁移
- `.env.example`
- 许可证、README、领域测试与持续集成配置

不交付安装包（exe、dmg）。不交付由作者部署、供陌生人打开的网站。安装包留到本机启动路径已经稳定之后再评估。

许可证使用 MIT。

## 2. 启动路径

README 写明一条路径：

1. 安装文档中标明的 Node 版本。
2. 复制 `.env.example` 为本地环境文件，按需填写模型地址、密钥和模型名。
3. 安装依赖并启动开发服务。
4. 浏览器打开本机页面。

`.env.example` 中每一项都有注释。真实密钥不进入仓库。

数据文件目录由 `DATA_DIR` 指定，默认在仓库外或仓库内被忽略的数据目录。README 说明如何备份这个目录。SQLite 文件放在 `DATA_DIR` 中。

`better-sqlite3` 是原生模块。README 写明 Windows 上缺少构建工具时的失败现象和处理办法。

## 3. 无模型密钥时的行为

未配置密钥，或显式使用本地假模型时：

- 项目看板、抽屉保存、简历编辑、Markdown 导出、PDF 打印可用。
- AI 提炼、关键词提取、匹配原因、合并候选句不可用，界面说明未配置模型。
- 领域测试使用假模型，不访问网络。

假模型返回固定 JSON，供测试和界面演示走完校验分支。

## 4. 数据所有权

README 用单独一节说明：

- 档案、项目事实、待补问题、JD 原文和简历保存在本机 SQLite。
- 只有使用者触发模型能力时，相关文本才会发往 `OPENAI_BASE_URL` 指向的服务。
- 应用不包含默认遥测，不把使用数据发回作者。

从第一版起使用数据库迁移。已有数据的使用者升级版本时，通过迁移升级结构，不要求删库。

提供全量 JSON 导出和导入，覆盖档案、项目、岗位、关键词、简历版本、简历条目和合并提案。这是换电脑和离开本应用的路径。简历 Markdown 导出不能代替全量备份。

## 5. 仓库里必须能读到的规则

README 开头说明这是本地职业工作台，并链到：

- [产品需求](product.md)
- [技术方案](../careerdesk-mvp-design.md)

README 同时写明匹配分由规则计算，模型只负责提取关键词、撰写匹配原因和生成简历句。分数规则的测试放在持续集成里，没有密钥也能运行。

持续集成至少运行这些领域测试：状态加权、计划中项目不进入默认勾选、简历句中的数字必须能在事实中找到、母版唯一、投递版改写不回写项目简历句。

## 6. 示例与空库

克隆后第一次启动是空库和空白母版。示例数据放在仓库的 `fixtures` 中，只能通过应用内的「导入示例数据」写入。示例人物与项目来自原型，并在 README 中标明为虚构演示。

## 7. 设置

同步母版的检查间隔持久化在本机设置中，默认 7 天。不把「每周五」写死。设置随全量 JSON 一起导出。

## 8. 验收

- 按 README 在一台新环境完成本地启动，打开后是空状态。
- 不填写模型密钥时，可以新建项目并导出一份 Markdown。
- 填写密钥并在文档说明的兼容接口上，可以完成一次提炼或一次岗位匹配。
- 导出的 JSON 在清空 `DATA_DIR` 后可以导回，项目、岗位和投递版改写仍在。
- 仓库中不包含真实密钥、真实 JD 或作者的私人职业材料。
- 持续集成在无密钥环境下通过领域测试。

## 9. 不在本版交付

安装包、自动更新、Docker 镜像、作者运营的在线演示（若演示会接收使用者的 JD 或事实）、账号体系和遥测。
